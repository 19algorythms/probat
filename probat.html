what probat can and cannot do

works, self-healing

  • full python stdlib — exact bigint arithmetic, fractions, hashlib
  • scientific stack shipped with pyodide: numpy, sympy, scipy, pandas
  • pypi pure-python packages via the deps field (micropip)
  • upload / drop .py and .json per run (the ⬆ button in each run's header, or drop files straight onto the cell) — uploads are seeded into the virtual filesystem
  • with a json box: its content is exposed to the script as DATA and compiled into the verified table after the run. without one: if the script writes .json files, the largest is auto-loaded back into the box and compiled — any other written file stays available in the export panel
  • fs bridge: a path your script opens but that does not exist is auto-completed from your uploads or editor content (warns in orange when it guesses); stale bridges are revoked before every run
  • module bridge: a missing import is installed on the fly, then the run retries
  • files your script writes become downloadable (export panel)
  • big integers stay exact in the compiled table — never rounded past 253
  • every run executes in a fresh namespace — no globals leak between runs; each run behaves exactly as in a brand-new page, even for completely unrelated scripts
  • runs queue: pressing ▶ while another run is active lines the run up instead of interleaving two executions in the engine; timing starts when the run actually starts
  • cross-run file collisions are warned in orange — if a run overwrites a file another run wrote, the console says who owned it first
  • freeze: the page regenerates itself with your content embedded — the file writes itself; its sha-256 fingerprint is recomputed on every keystroke

hard browser limits — never

  • multiprocessing / subprocess — wasm is single-process (multi-core engines stay in the forge)
  • C extensions not ported to pyodide: gmpy2, cypari, any package with compiled code — micropip will fail honestly
  • arbitrary network calls (CORS): no fetching URLs outside the pypi CDN
  • persistence: the virtual filesystem lives for the page session only — export what you want to keep
  • heavy scans do run, but on the visitor's cpu and without native acceleration — probat verifies, the forge computes

sketch
each run is an independent python + json pair with its own clock, console, compiled table and column histograms. add runs with ＋ run, rename them, delete them — the compare panel confronts any two verified executions: wall-clock race, row diff (added / removed / changed, joined on a unique key when one exists) and crossed distributions. the sha-256 fingerprint covers every run and the deps field. freeze forges a lapis: a sealed stone that re-verifies every run on open. uploaded files live in pyodide's virtual filesystem; missing paths are bridged, stale bridges revoked, missing modules installed on the fly. heavy scans run on your cpu — probat verifies, the forge computes.
